# Project: Aesthetic Match

## Purpose

To build a standalone web application that remembers and creates PERSISTENT fashion aesthetic recommendation from 5-10 fashion influencers (via image upload/URL), matches it against a live multi-brand catalog from real Shopify stores, and returns explainable, ranked product recommendations instead of "one-time image upload similar products recommendation".

This is positioned as a concept for the "Shop App" (Shopify's aggregated order tracking platform) feature.

## Target User

A woman who shops online and wants curated recommendations pulled from multiple independent brands that suit her personal aesthetic/style archetype, rather than browsing one store at a time. This should inform product, catalog, and UI decisions in every remaining phase -- e.g., don't add men's/unisex brands back into the seed list without revisiting this, and copy/imagery choices in the UI phase should speak to this user specifically.

# Scope

## In Scope

### Shopify catalog ingestion from curated public `/products.json` endpoints
- pull real inventory from real Shopify-powered fashion brands via each store's public /products.json endpoint. 
- The ingested catalog has a curated, archetype-diverse seed list, health-checking (detects disabled endpoints / bot-challenge pages, doesn't just crash on them), politeness controls, variant-to-product collapsing, and a global cap with round-robin trimming so no single store dominates. 
- Report back the real yield (how many stores came back ok vs blocked vs disabled) before we decide whether to add more stores, don't assume the seed list works, verify it.

### Vision tagging using Claude with a strict taxonomy
- for each catalog product's image AND each influencer reference image, call Claude's vision API for structured JSON output. Use the following taxonomy just as a reference but do not let scoring synonym drift between calls as it silently breaks exact-match ranking:

{

  "archetype_primary": "one of: coastal_grandmother | old_money | clean_girl_minimal | streetwear_athletic | cottagecore_romantic | scandi_minimal | trend_forward | edgy_alternative | bohemian",

  "archetype_secondary": "same enum, or null - for looks that blend two aesthetics",

  "silhouette": ["1-3 of: oversized | fitted | relaxed | structured | boxy | flowing | tailored"],

  "formality": "one of: loungewear | casual | elevated_casual | business | formal | vacation | college",

  "color_family": ["1-3 of: neutral_cream | earth_tone | monochrome_black | pastel | jewel_tone | bright_bold | denim_blue | metallic"],

“fabric”: “the item’s material or composition, e.g. ‘100% silk or mostly natural fabric or 100% polyester’’ - not used in scoring”,

  "texture_notes": "short free-text phrase, e.g. 'nubby linen weave' - flavor for rationale generation ONLY, never used in scoring"

}

Scoring weights: archetype_primary heaviest, silhouette and formality medium, color_family light-medium, texture_notes and fabric excluded from scoring entirely (it exists only so rationale text doesn't sound robotic).

- enforce this schema via Claude's tool use (forced tool_choice) with enum constraints on archetype_primary, silhouette, formality, and color_family, not a prompt asking for JSON in prose. Prompt-only JSON will drift off-list occasionally at this call volume, and a single off-taxonomy tag fails silently (it just won't match anything). 
- Validate the response against the enum in code as a cheap second safety net; 
- Retry once on schema failure.
- Cache every successful response using image hash.
- Never re-tag identical images.

Cache by product handle / image hash so re-runs don't re-spend. If more than ~15% of tagged items can't be confidently placed in the archetype enum, that's a signal the taxonomy needs a category added, report it, don't force a bad fit silently.

### Matching + Ranking
- weighted tag overlap + palette distance between the user's profile and each catalog item.
- no mock data
- Score should degrade gracefully when overlap is sparse; don't assume every request returns great matches.

Rules

- Exact enum matches only
- Ignore fabric during scoring
- Ignore texture during scoring
- Penalize sparse overlap gracefully
- Never return duplicate products
- Return Top 20

Generate rationale after ranking.

### AI-generated recommendation rationale
- one-line "why this matches" per recommendation, generated by Claude, referencing the specific shared tag(s)/influencer, not a generic template.

# Non-Functional Requirements

Performance

- Recommendation <3 seconds
- Catalog sync resilient to failures
- Cache all AI outputs
- 95% success

Reliability

- Retry failed AI calls once
- Continue ingestion if one store fails
- Gracefully handle empty results

Security

- Secrets in environment variables
- Validate uploaded images
- Reject unsupported formats

Observability

- Structured logs
- Catalog sync summary
- Claude latency
- Cache hit rate

Scalability

- Support 50–100 concurrent users.

Design services to remain stateless.
